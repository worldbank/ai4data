# Practical Guide to Refining Data Snapshot Metadata Extraction Policies with Model Councils

**A cookbook for data scientists, ML engineers, and AI application developers.** Version 0.1 (working draft), November 2026.

:::note[Working draft]
This guide documents a proposed experiment. The snapshots and published human-reviewed annotations are real. All round extractions, reviews, deliberations, and policy revisions are illustrative. The council experiment has not been executed.
:::

A model can return well-formed snapshot metadata and still mistake an axis label for a title or infer a unit the image does not establish. The proposed experiment keeps the reference extractor fixed while a model council uses diagnostic findings and human review to refine the extraction policy.

This practical guide takes a team from preparing a batch through drafting a revised policy and planning an independent evaluation. The [Data Snapshot dataset](https://huggingface.co/datasets/ai4data/data-snapshot) contains more than 3,900 snapshots. The [gold metadata release](https://huggingface.co/datasets/ai4data/data_snapshot_metadata_gold) contains 102 human-reviewed records.

## Prerequisites

- Familiarity with multimodal model inference, prompts, structured outputs, and basic evaluation.
- Existing snapshot crops, their source references, and the [Data Snapshot Metadata Schema v1.4 reference](/docs/data-snapshots/metadata-schema/).
- A human reviewer who understands the metadata schema and can assess extraction issues against the source evidence.

## First steps

1. Assign responsibilities and trace the round using [the workflow chapter](./workflow.mdx). Allow about an hour.
2. Verify the four images, reference associations, and versioned starting conditions using [the preparation chapter](./preparation.mdx). Allow about two hours.
3. Compare the illustrative outputs and findings, then trace the decisions through [diagnosis](./diagnosis.mdx) and [deliberation](./deliberation.mdx). Allow about two hours for discussion.

The [self-assessment](./start-here.mdx) helps identify a starting point. The final chapters specify proposed orchestration and the evidence needed before adopting a revised policy.

## Running example

| Sample | Batch | Snapshot and focus |
|---|---|---|
| D1 | Discovery | The Shona labor-force chart distinguishes a caption from an axis label. |
| D2 | Discovery | The WPS5070 rural Indonesia regression table distinguishes variables, statistics, and lag groupings. |
| C1 | Challenge | The Shona demographics table has row-specific units and a crop that excludes the caption. |
| C2 | Challenge | The WPS4771 guarantee-systems chart shows categories and legend entries but leaves the counted entity unspecified in the crop. |

The sample register pins the dataset revisions, source pages, and image fingerprints. The [preparation chapter](./preparation.mdx) explains the pairings and reuse information.

## Scope of the examples

The example illustrates one round, from the starting policy and state (P001 and S001) to the candidate policy and updated state (P002 and S002). The walkthrough uses selected fields to make each decision inspectable. Observations across rounds would be needed to assess stabilization, and independent evaluation would measure extraction quality. Distinguishability judging, fine-tuning, and operational deployment are outside this design.
