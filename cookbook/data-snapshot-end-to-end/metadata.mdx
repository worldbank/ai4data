# 3. Semantic metadata extraction

**Question:** How is a data snapshot described in structured metadata?

## Rationale

The two data snapshots selected in [chapter 2](./snapshots.mdx) are the inputs to the metadata stage. This stage uses a vision-language model, which processes an image together with text instructions. Its response is validated against the canonical Data Snapshot Metadata Schema v1.4 before a JSON file is saved.

Metadata fields describe analytical meaning: measured variables, their units, grouping dimensions, temporal coverage, visible sources, and related context. They do not hold a reconstructed numerical dataset. Missing and null fields represent unavailable information. Validation only checks for structural integrity and does not establish that the model interpreted the image correctly.

## Target state

- The selected figure and table have corresponding metadata records.
- The reader can interpret each record without treating it as transcribed data.

## Maturity levels

| Level | Steps |
|---|---|
| **Foundational** | A curator describes visible variables, units, groups, and missing context in notes alongside a data snapshot. |
| **AI-ready** | The selected images receive schema-constrained model descriptions, and the raw JSON records are validated and interpreted separately from numerical observations. |
| **AI-native** | An organization integrates model-assisted metadata generation with validation and human review before reuse. Additional integration is needed to monitor semantic quality and manage corrections. |

:::info[Running example]
Only the chart `figure_001` and table `table_000` selected in chapter 2 are submitted for metadata extraction. Each has a corresponding raw JSON record for inspection.
:::

2. Inspect `variables` for measured concepts and units, `dimensions` for population groups or year columns, and `visualization_types` for the represented form.
3. Distinguish source wording in `source_text` from a controlled representation in `normalized_value`. A normalized interpretation must not be passed off as printed wording.

**Worked example.** The figure record identifies employed and unemployed populations and the two population groups. Its `title` is `Percent of population`, which is visibly the vertical-axis label. The model may have confused this prominent label with a title, particularly because the printed caption is outside the data snapshot. The record can validate while this field remains questionable. The model's geographical coverage is null; the document's Kenya context is not provided as extra evidence.

The table's `title` is `null`, while its metadata identifies variables such as `Median age` and `Mean household size`, a `Year` dimension with 2019 and 2024 categories, and `table` as the visualization type. Its title and source are outside the data snapshot, but that observation does not establish why the model returned a null title. The table illustrates missing title metadata alongside useful descriptions; the figure illustrates a questionable inference from an axis label. Inspecting each data snapshot alongside its JSON distinguishes an unpopulated field from a populated field that misinterprets visible text.

## Implementation options

The top-level Python `extract_metadata(image_path, config_path=...)` returns an `ExtractionResult` with diagnostics, response status, usage when returned, and validated metadata. A custom config path is supported there even though the CLI chooses packaged presets. The schema's version is exported schema metadata and is not required in individual records.

## Common mistakes

- Equating schema validation with factual verification leaves interpretation errors undetected.
- Submitting incomplete data snapshots that omit titles, footnotes, or legends can lead to incomplete or inaccurate metadata.
- Assuming an ordinary metadata rerun validates existing JSON files leaves invalid records unchecked.

## Verification

- Match each selected PNG to a JSON file with exactly the same stem in the metadata directory. The recorded exercise has two selected-image responses; the remaining detector candidates intentionally have no metadata.
- If repeating validation locally, run `inspect_metadata.py` on each downloaded JSON. A zero exit status and a display of populated fields indicate that the record satisfies the canonical model; the script should leave the input file unchanged.
- Compare populated fields with the visible text and structure of each data snapshot to identify questionable interpretations.
