# 9. Metadata review with the local editor

**Question:** How can a curator review and update data snapshot metadata?

:::note[Optional chapter]
This chapter demonstrates one tool for carrying out the review described in [chapter 4](./review.mdx). It can be skipped when metadata is reviewed using other tools.
:::

## Rationale

[Chapter 4](./review.mdx) identifies interpretation errors by comparing data snapshots with their metadata and the source page. The local metadata reviewer provides an editor for applying those findings. It displays an image beside structured fields, shows the generated values for comparison, and saves a separate reviewed JSON record.

The generated record remains evidence of the model's response. A reviewed copy records the curator's edits without replacing that reference. The app checks the saved record against Data Snapshot Metadata Schema v1.4, while the curator remains responsible for judging whether each field accurately describes the visible content.

This chapter can be completed with the four recorded files provided below. It requires Python 3.11 or later and the reviewer extra, with no detector weights, provider credentials, or new metadata requests.

## Target state

- The recorded chart and table can be opened beside their generated metadata.
- The chart's axis-label title finding has been addressed in a separate reviewed record.
- The reviewed record validates, and the generated reference remains available for comparison.

## Maturity levels

| Level | Steps |
|---|---|
| **Foundational** | A curator compares a data snapshot with its metadata and records an interpretation finding. |
| **AI-ready** | The curator saves a schema-valid correction separately from the generated reference and verifies the result. |
| **AI-native** | An organization connects reviewed records to monitored quality checks and coordinated review. That integration requires additional tooling. |

:::info[Running example]
The chart `figure_001` and demographic table `table_000` are the same data snapshots used in chapters 2 to 4. The chart's generated `title` contains `Percent of population`, which appears on its vertical axis. The worked correction removes this title because no title is visible inside the data snapshot.
:::

## Recipes

<Recipe title="9.1 Open the recorded data snapshots for review" level="AI-ready" skills="Developer and data curator" time="Ten minutes for setup and file preparation, plus installation time">

**Result:** The local editor displays the two recorded image–JSON pairs without submitting new model requests.

The reviewer is an optional part of `ai4data`. Its installation supplies the browser interface and schema dependencies without installing a detector or a metadata provider SDK. Run the following command from the repository root in the intended Python environment. The source installation is used until a release includes the app.

```bash
python -m pip install ".[data-snapshot-metadata-reviewer]"
```

1. Create `output/cookbook-data-snapshot-review/snapshots/` and `output/cookbook-data-snapshot-review/metadata/` as a fresh review exercise directory. If the exercise directory already contains reviewed outputs, choose a new directory and use its path in the launch command below. This preserves previous work and reproduces the initial unreviewed state.
2. Save the PNG downloads below in `snapshots/` and the matching JSON downloads in `metadata/`. Preserve their full filenames so each image and JSON have the same stem, which is the filename without its extension.

   | Material | Image | Generated metadata |
   |---|---|---|
   | Employment chart, `figure_001` | [Chart PNG](pathname:///cookbook-files/data-snapshot-end-to-end/policy_brief_on_shona_community_from_stateless_to_citizens_figure_001.png) | [Chart JSON](pathname:///cookbook-files/data-snapshot-end-to-end/policy_brief_on_shona_community_from_stateless_to_citizens_figure_001.json) |
   | Demographic table, `table_000` | [Table PNG](pathname:///cookbook-files/data-snapshot-end-to-end/policy_brief_on_shona_community_from_stateless_to_citizens_table_000.png) | [Table JSON](pathname:///cookbook-files/data-snapshot-end-to-end/policy_brief_on_shona_community_from_stateless_to_citizens_table_000.json) |

3. Launch the reviewer with the prepared image directory. Its generated-metadata and reviewed-output roots default to sibling `metadata/` and `reviewed/` directories:

   ```bash
   python -m ai4data.data_snapshot.metadata_reviewer \
     --snapshots-root output/cookbook-data-snapshot-review/snapshots
   ```

4. Open the address printed in the terminal if a browser does not open automatically. The default address is `http://127.0.0.1:8501`. Confirm that the chart is shown as item 1 of 2 and that the **Title** field contains `Percent of population`.

The three directories have different roles:

| Directory | Role |
|---|---|
| `snapshots/` | The app reads the two image files as visible evidence. |
| `metadata/` | The app reads the generated JSON as the comparison reference. |
| `reviewed/` | The app creates this directory when saving a reviewed copy. Its JSON filenames match the input images. |

The reviewed directory must be separate from both input roots. Missing counterparts appear as discovery warnings, and duplicate stems stop discovery because the app cannot choose an unambiguous pair.

**Worked example.** The recorded local run on 11 November 2026 opened both original pairs with their full filenames. The chart appeared first, with zero reviewed records. The screenshot shows that initial state in the dark theme.

[![The dark-theme reviewer displaying the original chart and its generated title](/cookbook-files/data-snapshot-end-to-end/metadata-reviewer-dark.png)](/cookbook-files/data-snapshot-end-to-end/metadata-reviewer-dark.png)

**What this does not do.** Opening a pair does not mark it as reviewed. This exercise uses saved outputs and does not repeat extraction or establish coverage of the source PDF. The remaining candidate images from chapter 2 are outside this two-pair exercise.

<Recipe title="9.2 Correct and save the chart metadata" level="AI-ready" skills="Data curator" time="Fifteen minutes for the demonstrated correction and verification">

**Result:** A separate reviewed chart record omits the incorrectly assigned title and retains the other generated metadata values.

The generated title repeats the vertical-axis label. A title is a heading or caption identifying the data snapshot; an axis label describes the scale of its values. The source page contains a caption outside the extracted image, as documented in chapter 4. This correction therefore clears the title without copying that external caption into image-derived metadata.

1. In **Edit metadata**, select **Overview** and compare **Title** with the chart. The **?** control shows the generated field value, and **Generated reference** displays the full original JSON.
2. Clear **Title** and leave the field so the edit is applied. Its label becomes orange, and the toolbar reports **Unsaved edits**. A missing title is appropriate here because the available image does not show a title.
3. Select **Save reviewed & next**. The app validates the working record before writing its reviewed copy, then moves to the table. A validation error leaves the draft available for correction and preserves an existing saved file.
4. Select **Previous** to reopen the chart. Confirm that its status is **Reviewed**, its title remains blank, and **Generated reference** still contains the original title. The orange label identifies the difference from that reference.

The saved chart record is available at this path in the exercise directory:

```text
output/cookbook-data-snapshot-review/reviewed/policy_brief_on_shona_community_from_stateless_to_citizens_figure_001.json
```

The distinction between the two representations is:

| Representation | `title` |
|---|---|
| Generated reference | The value is `"Percent of population"`. |
| Reviewed copy | The field is omitted because no supported title remains. |

Saving uses the canonical schema's normalization and omits null fields. Missing and null object fields are treated as equivalent for comparisons. Other omitted null fields in the saved JSON therefore do not represent additional semantic corrections.

**Worked example.** The recorded run cleared the chart title, saved the record, and reopened it through **Previous**. The saved JSON validated against the canonical model. Comparing canonical representations confirmed that removing the title was the only semantic change, and the original image and generated JSON retained their original bytes.

[![The dark-theme reviewer after reopening the saved chart, with a blank orange title and reviewed status](/cookbook-files/data-snapshot-end-to-end/metadata-reviewer-reviewed-dark.png)](/cookbook-files/data-snapshot-end-to-end/metadata-reviewer-reviewed-dark.png)

The [recorded reviewed JSON](pathname:///cookbook-files/data-snapshot-end-to-end/reviewed-figure-001.json) is a downloadable copy of that output with a shorter download name. It can be compared with the original chart JSON without running the app. It belongs outside the generated-metadata input directory.

The **Structure**, **Temporal**, **Geographic**, and **Context** sections expose the remaining nested fields, including lists that can be added, removed, and reordered. Each field includes its schema definition and examples. A full review would inspect those values individually; this recorded exercise demonstrates the title correction only.

**What this does not do.** A file marked **Reviewed** records that a save occurred. The demonstrated edit does not certify every other field or create benchmark ground truth. Drafts have no autosave, and closing or reloading a session can lose unsaved work. Navigation within the app offers **Save & move**, **Discard & move**, and **Cancel** when edits are pending.

</Recipe>

## Implementation options

The same editor can open existing pipeline outputs by supplying their `snapshots/` directory. For example, the outputs from chapter 3 can be opened with `--snapshots-root output/cookbook-data-snapshot/doclayoutyolo/snapshots`. Images without matching JSON will appear as warnings, including candidates that were deliberately excluded from metadata extraction.

When metadata and reviewed copies are stored elsewhere, use `--generated-root` and `--reviewed-root` to supply those locations explicitly. A text editor remains an alternative for editing JSON, followed by validation with the existing [inspection helper](./metadata.mdx#recipe-3-2). The app guide documents [file matching, navigation, and save behavior](https://github.com/worldbank/ai4data/blob/main/src/ai4data/data_snapshot/metadata_reviewer/README.md).

## Common mistakes

- Renaming an image without renaming its JSON prevents the app from matching the pair.
- Copying a caption from outside the data snapshot into image-derived metadata changes the evidence boundary of this workflow.
- Treating **Reviewed** as a guarantee of semantic accuracy overstates what the app records.
- Editing the same output directory in multiple sessions can overwrite another session's saved changes because there is no conflict detection.
- Reusing reviewed outputs after regenerating inputs can conceal work that needs another review. Previous reviewed copies should be moved aside before starting a fresh review of regenerated inputs.

## Verification

- The prepared directories contain two matching image–JSON pairs, and the app reports two items.
- The reopened chart has a blank title and a reviewed status, while its generated reference retains `Percent of population`.
- The reviewed JSON satisfies Schema v1.4, and its canonical content differs from the generated record only by removal of the title.
- The image files and generated JSON retain their original contents. Use Ctrl+C in the terminal to stop the app after inspection.
