# Practical Guide to the Data Snapshot End-to-End Workflow

**A cookbook for developers and data curators working with institutional PDFs.** Version 0.1 (working draft), October 2026.

:::note[Working draft]
This guide is working material of the AI for Data – Data for AI program. It does not represent official World Bank Group guidance or policy. The [contributing page](./contributing.md) explains how to report corrections and propose reviewed examples.
:::

Institutional reports contain charts, tables, maps, and monitoring summaries whose analytical meaning depends on their visual structure. A data snapshot preserves a bounded analytical region as an image. The production `ai4data.data_snapshot` workflow detects candidate regions and can describe their visible content with structured semantic metadata.

This guide follows the practical questions involved in preparing a PDF, extracting data snapshots, generating metadata, and reviewing the files. It then explains combined execution, recovery, model selection, and proposed improvements. The recorded workflow processes the sample PDF used in the tutorial with DocLayout-YOLO and includes separate metadata requests for one figure and one table.

The result is a set of PNG images and Schema v1.4 JSON files. Numerical transcription, publication, search, and other downstream processing are possible next steps, covered separately by the [Extracting Data from Documents cookbook](/cookbook/data-from-documents/). This guide is self-contained for the Data Snapshot workflow and does not require completing that cookbook first.

## Prerequisites

- Python 3.11 or later, an isolated environment, and a checkout of the repository.
- A developer can install optional dependencies and run commands; a curator can inspect institutional charts and tables.
- The sample PDF used in the tutorial is downloaded from its publisher following [chapter 1](./preparation.mdx).
- Metadata execution requires an authorized provider key and credits. Snapshot-only execution does not require that key.

## First steps

The shortest path uses the recorded example's default configuration and the two selected data snapshots. Alternative models can be considered after these outputs have been reviewed.

1. Prepare the sample PDF and Python environment in [chapter 1](./preparation.mdx). The examples use DocLayout-YOLO on CPU and the unchanged OpenRouter preset. Allow about forty minutes for preparation, plus dependency installation time.
2. Run snapshot-only extraction and inspect the chart and table in [chapter 2](./snapshots.mdx). Allow about twenty-five minutes for command preparation and data snapshot inspection, plus detector execution time.
3. Generate metadata for only those two data snapshots and inspect the JSON in [chapter 3](./metadata.mdx). The extraction script validates each response before saving; repeating validation is optional. Allow about thirty minutes for selection, submission, and local inspection, plus provider waiting time. The downloadable responses can also be inspected without making new requests.
4. Review the source pages, data snapshots, and raw responses in [chapter 4](./review.mdx). Allow about forty minutes to identify missing context and questionable metadata and consider the suggested next steps.

[Chapter 5](./combined.mdx) then explains the supported combined command and its expected output tree. [Chapter 6](./operation.mdx) covers recovery and request control, [chapter 7](./models.mdx) explains model selection and alternatives, and [chapter 8](./roadmap.mdx) describes proposed improvements. All times are indicative estimates of human work. They are not measured model runtimes or provider latency.

## Running example

The sample PDF used in the tutorial is the institutional publication *From Stateless to Citizens: The Journey of Shona in Kenya*. The [ReliefWeb report](https://reliefweb.int/report/kenya/policy-brief-stateless-citizens-journey-shona-community-kenya) links to the [PDF attachment](https://reliefweb.int/attachments/831aca28-6777-4cb9-9b84-8976c63061fb/Policy%20Brief%20on%20Shona%20community_From%20Stateless%20to%20Citizens.pdf). PDF page 4 contains both selected artifacts. Their numerical observations remain source content. No numerical transcription was performed for this guide.

The recorded detector output contains seven figure-labelled candidate images and one table-labelled candidate image, including an irrelevant photograph. The selected chart is `figure_001`; the existing gold dataset uses `figure_000` for a different extraction history. Those filenames are not interchangeable identifiers for reviewed metadata.

## Scope of the examples

The figure and table data snapshots are actual production outputs; their metadata records come from separate selected-image requests. The combined section shows the expected output layout for both stages. Other detectors are documented but not benchmarked here. The second-stage classifier and improvement roadmap are proposed extensions. The example was run on 30 October 2026 using DocLayout-YOLO 0.0.4, CPU, 300 DPI, and the unchanged packaged OpenRouter preset. The two JSON files are unedited model responses, with interpretation findings in [chapter 3](./metadata.mdx) and review observations in [chapter 4](./review.mdx).
